# 现象理解：把"结果"解释成"机制"，但要守住证据边界

> 提炼自 ARIS `analyze-results`（19.7k★，Observation→Interpretation→Implication→Next step）、
> ARS `academic-paper` 的写作质量/证据绑定要求、K-Dense `scientific-critical-thinking`，
> 以及实验科学中"相关 vs 因果"的标准判据。

## 0. 三层结构：观察 / 解释 / 推论

任何一条"发现"都要拆成三层，措辞强度逐层降低：

| 层 | 内容 | 允许的措辞 |
|---|---|---|
| Observation | 数据/日志显示了什么（含数字、条件、方差） | "we observed / measured" |
| Interpretation | 可能的原因/机制（可多个假设） | "this suggests / is consistent with / one explanation" |
| Implication | 对研究问题/应用意味着什么 | "if confirmed / in this setting / may" |

常见错误：把 Interpretation 写成 Observation；把 Implication 写成已被证明的结论。

## 1. Claim 强度阶梯（不许跳级）

1. **描述**：在某数据/设定上观察到差异；
2. **相关**：差异与某因素共变（控制可见 confound 后）；
3. **干预**：主动改变因素，差异随之出现/消失（消融、替换、冻结、控制实验）；
4. **机制**：能预测新情境，并被独立探针/理论支持；
5. **泛化**：跨数据/领域/规模成立（需要多设定证据）。

写 claim 时先定位自己在哪一级；措辞与证据级别一致。

## 2. 替代解释清单（逐条排除或承认）

- **Confound**：参数量、算力、训练步数、数据量、调参预算、实现质量、后处理。
- **选择偏差**：只挑成功 seed/样本/子集；数据收集偏差；评测集选择偏差。
- **测量误差**：指标计算错误、聚合方式、人类标注不一致、评测协议差异。
- **回归均值**：极端组在重复测量中自然回落。
- **Benchmark artifact**：评测集污染、格式偏好、指标饱和、leaderboard 过拟合。
- **实现差异**：baseline 用旧代码/不同库版本；我们用了更好的 trick 但归因给方法。
- **随机性**：单 seed、小数据、训练不稳定导致的偶然差异。
- **发表/选择偏差**：只看到成功案例，失败案例没被报告。

做法：在 results/discussion 里明确列出 2–3 个最可能的替代解释，并说明你做了哪个对照来排除/削弱它；排不掉的写进 limitations。

## 3. 用"探针"代替"讲故事"

| 假设 | 探针 |
|---|---|
| 组件 X 有效 | 删除/替换/冻结 X；控制容量与算力 |
| 机制是"利用 Y 信息" | 打乱/移除 Y；表征探针；干预后预测 |
| 增益来自表示质量 | 线性探针、最近邻、迁移评测 |
| 增益来自数据/规模 | 同算力/同参数对照；数据消融 |
| 现象只在某边界成立 | 逐 slice / 跨数据集 / 规模扫描 |
| 失败来自某类输入 | 错误分类、最差样本、混淆矩阵 |
| 趋势是真实的 | 换 seed/换数据重跑；看 CI 与方差 |

原则：每个解释至少配一个**能证伪它的最小实验**；写进"下一步实验"。

## 4. 读曲线与趋势

- **单调上升/下降**：检查是否只是训练更久/更大；给同预算对照。
- **U 型**：可能是正则/容量/学习率的权衡；用中间点消融验证。
- **平台**：方法可能饱和，或评测/数据到上限；换更难设定再判断。
- **断崖/尖峰**：先怀疑 bug/数值不稳定/数据异常，再解释为"涌现"。
- **两条曲线交叉**：注意交叉点附近方差；不要只挑交叉后的区间。
- **训练 loss 降但 eval 不降**：过拟合/泄漏/协议差异；先查数据与评测。

阅读顺序：方差 → 协议一致性 → 曲线形状 → 机制解释。

## 5. 统计与实用显著性

- 报效应量 + 置信区间；p 值只回答"是否有证据反对零假设"，不回答"效果多大"。
- 多重比较要校正；不要从 10 个指标里挑一个显著的讲。
- 交互效应 vs 主效应：某方法"平均更好"可能在某些 slice 更差；逐 slice 报告。
- 小样本/人类评估：给 CI 与一致性指标；不把 3 个样本的差异写成结论。
- 实用显著性：提升是否超过评测噪声/业务阈值；给出"最小有意义差异"。
- 等价性声明需要 equivalence test，不能因为 p>0.05 就说"相当"。

## 6. 错误分析与定性证据

- 错误分类要有**预定义类别 + 抽样规则 + 双人标注/一致性**（如适用）。
- 给每类错误的代表样例与频次；不要只放一个"成功案例"图。
- 逐 slice/群体指标（长度、类别、口音、域、难度）能揭示平均指标掩盖的问题。
- 定性例子要说明选取标准（随机/最差/典型），并注明是否 cherry-picked。
- 失败分析比成功展示更能建立可信度：审稿人信"你知道它何时失效"。

## 7. 负结果与边界

- 负结果/零结果有价值：写清设定、效应量、置信区间与可能原因。
- 边界条件是贡献：在什么数据/规模/领域下方法失效；给判据。
- "什么会推翻这个结论"必须能回答；答不出说明 claim 不可证伪。
- 不把失败藏进 appendix 只留成功；不把"没跑出来"写成"不适用"。

## 8. 把理解写成文字（Observation → Interpretation → Implication → Next）

推荐模板（ARS/ARIS 风格）：

```markdown
### Finding F1: <一句话发现>
- Observation: <数字、条件、方差、run id>
- Interpretation: <机制假设；与替代解释的区分>
- Evidence: <对照实验/探针/文献>
- Implication: <对研究问题/实践的意义；范围>
- Next: <能证伪该解释的最小实验>
```

每条 finding 都要能回到 `claim_map.json` 的证据；Interpretation 与 Observation 分开写。

## 9. 反模式

- 把 benchmark 领先写成"机制更优"
- 用相关性语言暗示因果（"X 导致 Y"没有干预实验）
- 只看主指标平均分，不看 slice/方差/失败样例
- 结果出来后编机制故事，没有可证伪预测
- 忽略相反证据/矛盾 slice；只报支持假设的部分
- 把"没显著差异"写成"等价/无影响"
- 把单 seed 的波动解释成"涌现能力"
- 过度 hedge 到没有结论，或过度自信到超出证据

## 10. 与写作/报告的结合

- 论文 Results 先写 Observation，再写 Interpretation（可放 Discussion）；不要把两者混成一句。
- Discussion 的每个机制句都要有探针/对照或文献支撑；否则标为 hypothesis。
- Limitations 写清"哪些解释没排除"；这比空泛的"未来工作"更可信。
- 返修时若审稿人质疑机制，优先补"能区分竞争假设"的实验，而不是加形容词。
