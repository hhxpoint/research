# 作图：让图先忠于证据

> 提炼自 K-Dense `scientific-visualization`（58.3k★ 仓库，v1.4，含 integrity/accessibility guardrails）、
> ARS `statistical_visualization_standards` 与 `vlm_figure_verification`、期刊投稿实践。
> 目标不是"图漂亮"，而是**读者能在 10 秒内正确读出结论，且这个结论经得起追问**。

## 0. 先回答三个问题（写代码之前）

1. 这张图要支持论文里的**哪一句 claim**？把原句写下来。
2. 读者需要比较什么、看趋势、还是看分布？——这决定图型，而不是反过来。
3. 数据从哪来、做了什么变换、误差代表什么？答不出就不许画。

如果一张图支持的结论和正文 claim 对不上，删图或改 claim，不要改数据。

## 1. 数据与诚信（不可协商）

- 不修改、不隐藏、不发明、不选择性增强数据；不删点、不截断、不调坐标轴来"让结论更好看"。
- 保留原始表、排除规则、缺失值编码、分析代码、归一化/分箱/平滑参数、图像处理记录、随机种子。
- 缺失值要区分**缺失 / 零 / 删失 / 被排除**，用断线、显式标记或图注说明，不能用平滑线偷偷连过去。
- 图像类数据保留原图，说明全图调整（亮度/对比度/裁剪），给比例尺，不擦除背景。
- 图里每个数字要能回溯到源数据/脚本；交付时附 provenance（数据路径、变换、误差定义、种子）。

## 2. 图型与编码

| 要表达 | 首选 | 不要用 | 原因 |
|---|---|---|---|
| 类别比较 | 点图/条形图（从 0 开始） | 3D 柱、面积夸张 | 长度/面积必须从基线量起 |
| 分布 | 箱线/小提琴 + 原始点（抖动） | 只画均值±误差 | 隐藏双峰/离群/样本量差异 |
| 趋势 | 折线 + 不确定性带 | 双 y 轴 | 双轴容易制造伪相关 |
| 相关 | 散点 + 拟合/分箱 | 只给相关系数 | 掩盖非线性/离群 |
| 构成 | 堆叠条（有限类别） | 饼图（多类） | 人眼不擅长比较角度/面积 |
| 矩阵/热图 | 有序色图 + 色标 + 数值 | 彩虹色图 | 亮度不单调，误导数值 |
| 高维 | 降维（UMAP/t-SNE）+ 说明 | 把降维坐标当"距离" | 降维不保距 |

- **零基线**：条形/面积必须包含 0；点线图可以非零，但要披露断轴并给参照线。
- **双轴**：优先拆成两个对齐面板；非用不可时说明两个轴的单位与量级，禁止调刻度制造"同步"。
- **对数轴**：标注底数与变换；说明 0/负值如何处理。
- **分箱/平滑**：记录边界、窗口/带宽、方法，并给敏感性检查（换参数结论是否变）。
- **归一化**：写公式与参照；比较面板之间保持同一范围。
- **面积/体积**：按面积/体积缩放，不按半径/直径；不用装饰性 3D。
- **样本量**：类别样本量差异大时，标 n 或用比例；不要让大类的抖动吞掉小类。

## 3. 不确定性与统计

- 误差线必须写明：**SD / SE / 95% CI / 分位数 / 后验区间**，并说明 `n` 与重复单位（seed / subject / sample）。
- 有重复测量时按独立单位聚合（如 subject-level bootstrap），不能把行当独立样本算 CI。
- 图注要能自含：图型、变量、单位、样本量、误差定义、统计检验、显著性标记含义。
- 不要用 `*` 星号而不说明检验与多重比较校正；不要用"无重叠即显著"。
- 重要比较给效应量与 CI，不只给 p 值；小样本不要画太光滑的拟合曲线。

## 4. 可访问性与配色

- **颜色冗余**：颜色 + 形状/线型/纹理/直接标注至少两种编码；色盲与灰度下都能区分。
- **色图选择**：定性用分类色板（如 Okabe–Ito）；顺序用单色阶；发散用双向色阶并在 0 处居中；循环量用循环色图。禁止彩虹色表示连续量。
- **对比度**：最终尺寸下检查前景/背景对比（图形对象 ≥3:1，文字按 WCAG 参考 4.5:1）；不要依赖"浅色差异"。
- **文字**：轴标签含单位；图例不遮挡数据；不要用缩写除非图注定义。
- 交互图不能替代静态可读性；网页交付给 alt text + 底表。

## 5. 排版与导出

- 先确定**最终物理尺寸**（单栏/双栏 mm），按该尺寸排版；字号 ≥7pt（多数期刊下限），面板标签一致。
- 多面板：同一量纲共享轴；面板标签 (a)(b)(c) 左上角一致；顺序符合正文引用顺序。
- 导出：矢量优先（PDF/SVG/EPS）；栅格 ≥300 dpi（线条图 600 dpi）；嵌入字体或确认期刊允许 path；白底不透明。
- 不要用 `bbox_inches="tight"` 偷偷改页面尺寸；用固定 figsize + constrained layout。
- 交付文件命名 `fig1_<slug>.pdf`，同时保留生成脚本与数据源；导出后**回读文件**检查尺寸/字体/裁切。

## 6. 审查流程（交付前逐项过）

1. 把图缩到最终尺寸，在论文上下文里看：能一眼读出 claim 吗？
2. 灰度打印/灰度屏幕看一遍：还能区分吗？
3. 逐个数字对照源表：坐标、标注、文本里的数字是否一致？
4. 检查坐标范围、断轴、误差定义、样本量、单位、显著性说明。
5. 检查图注是否自含；正文是否引用了每个面板。
6. 检查文件元数据：尺寸、dpi、字体、颜色模式、是否被裁切。
7. 问一句："如果结论是反的，这张图会是什么样？"——如果两种结论看起来差不多，图不合格。

## 7. 反模式清单（命中即返工）

- 双 y 轴制造伪相关；截断条形图 y 轴放大差异
- 误差线没有定义；只画均值不画分布/样本量
- 平滑曲线隐藏缺失点/离群点；不说明平滑参数
- 彩虹色热图；红绿对比作为唯一编码
- 3D 柱/饼图；面积按半径缩放
- 每张图坐标范围/配色/字号不一致，读者需要重新学习
- 图注只写"结果如图"；正文没有引用面板
- 图片被过度增强/裁剪改变含义；上采样冒充细节
- 用一张图同时支持三个 claim；面板之间量纲不可比
- 只挑好看的 seed/子集画图，失败结果不展示

## 8. 与本仓库工具链的配合

- 用 `scientific-visualization` 技能做 style/配色/导出/元数据检查（它带 `figure_export.py`、`image_metadata.py`、`palette_audit.py`）。
- 用 `venue-templates` 确认目标期刊的图宽/字号/格式要求（以官方最新 guide 为准）。
- 用 `office-render` 检查 Word/PDF 中的最终版式。
- 把图、生成脚本、源数据、provenance 一起提交；`auto-research` 的 claim_map 引用图表路径。
