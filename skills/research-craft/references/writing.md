# 写作：把研究工作写成可被审稿人接受的论证

> 提炼自 ARS `academic-paper`（58.3k★，11 模式 / 6 种论文类型 / 5 种引用格式 / 写作质量检查 / anti-patterns）、
> K-Dense `scientific-writing`（58.3k★，evidence binding / reporting guidelines / no fabrication）、
> 以及顶会审稿实践。目标：**每个 claim 有证据、每段有功能、每句话读者不需要猜**。

## 0. 写作前必须有

- 一句话研究问题 + 主 claim（≤2 个）+ 必须排除的反 claim；
- 证据清单：每个 claim 对应的实验/图/表/引用（没有就先去补，不要先写）；
- 目标 venue：类型、页数/字数、模板、匿名要求、引用格式、AI 使用政策（以官方最新为准）；
- 数据/代码可用性与局限性的素材。

先把"证据 → claim"表写出来，再动笔。没有证据的段落不属于论文，属于未来工作。

## 1. 故事脊柱

```
问题（现实/理论上的空白）
  → 现有方法的局限（为什么不够）
    → 我们的洞察（一句话机制假设）
      → 方法（如何实现这个洞察）
        → 证据（主实验 + 必要消融/分析）
          → 边界（适用范围、失效条件、局限）
```

- 主 claim ≤2：一个主贡献 + 一个可选支撑贡献；贡献越多，证据越薄。
- 先写"反 claim"：例如"增益只来自更多参数/更大搜索空间/更长训练/benchmark 伪影"，然后设计对照。
- 每个 section 只服务脊柱上的一个环节；写不出功能就删。

## 2. 标题与摘要

**标题**：具体方法/发现 + 任务/场景；避免"Towards/Exploring/A Study of"这类无信息开头；不夸大范围。

**摘要公式（150–250 词）**：
1. 背景/问题：1 句，读者能懂为什么重要；
2. 空白：1 句，现有方法缺什么（可含数字）；
3. 做法：1–2 句，机制级，不是"我们提出一个框架"；
4. 关键结果：1–2 句，**带具体数字与对比基线**；
5. 意义/边界：1 句，适用范围或局限。

检查：摘要里的数字必须与正文表格完全一致；摘要不能出现正文没有的 claim。

## 3. Introduction（漏斗 + CARS）

- **Territory**：这个领域在做什么、为什么重要（不要教科书式铺陈）。
- **Niche**：现有工作做到哪、缺什么（用 3–5 篇最近最强工作定位，不是清单）。
- **Occupation**：我们怎么做、贡献是什么、证据是什么（一段话讲完）。
- 贡献列表 2–4 条，每条可检验：`we show that <X> under <Y> by <evidence>`，避免"we propose a novel framework"。
- 引用 nearest prior work 并说明差异；"first to" 必须能被检索验证，否则别写。

## 4. Method

- 按"实际做了什么"写，读者能复现：数据来源/划分、预处理、模型/算法、损失、超参搜索空间、训练预算、硬件、随机种子、评测协议。
- 关键设计给**动机**（为什么这样设计），但不要把 related work 塞进来。
- 复杂公式前先用一句话说清直觉；符号表统一，首次出现定义。
- 隐藏的坑要写：数据清洗、失败尝试、实现细节（batching、精度、梯度裁剪）。
- 方法图与正文一致；图中每个模块在正文有对应解释。

## 5. Experiments / Results

- 按 claim 顺序组织：主结果 → novelty 隔离 → 简洁性/必要性 → 失败分析。每张表图只回答一个问题。
- 主表：最强基线 + 我们的方法 + 必要变体；同一评测协议、同一数据划分、同一调参预算；注明 seeds 与 mean±std/CI。
- 数字写法：`ours 42.1 ± 0.3 vs best baseline 39.8 ± 0.5 (n=3)`；差值给相对/绝对提升；显著性与效应量分开说。
- 负结果、失败运行、超参敏感性照写；不把非显著说成"相当/持平"（equivalence 需要 equivalence test）。
- 消融：一次只动一个变量；给删除/替换对照；说明"去掉后变差"不等于"机制成立"。
- 定性例子要代表性，不能只挑成功案例；给出选取规则。
- 表格：数字右对齐、单位、最优加粗规则一致、图注自含；不在正文重复整张表。

## 6. Related Work

- 按"轴"组织（问题设定/方法族/评测），不是按论文列表；每段结尾回到"我们与它的区别"。
- nearest prior work 必须逐个对比：设定差异、方法差异、证据差异；不要只写"also related"。
- 引用要准确：不要把别人的设定说成你的设定；不要把综述当原始工作；引用最近 12–24 个月的强工作。
- "novelty" 是相对的：写清相对哪篇工作、在哪个维度新；没有 nearest prior work 的 novelty 声明不可信。

## 7. Discussion / Limitations / 声明

- Discussion 只做三件事：解释主发现（机制）、与文献对话、给边界；不引入新结果。
- Limitations 具体化：数据规模/领域偏移/评测局限/算力/单一种子/人类评估偏差；不要写"未来工作可以解决"当挡箭牌。
- 必含声明：数据可用性、代码、伦理（如适用）、作者贡献（CRediT）、利益冲突、资助、AI 使用声明。
- 结论强度与证据匹配：benchmark 赢不等于机制更好；单数据集不等于泛化。

## 8. 语言与风格

- 一段一个论点，主题句在前；段落之间用逻辑连接（因果/对比/递进），不用"此外/另外"堆砌。
- 主动语态优先，动词具体（"we measure"而不是"measurements are performed"）。
- 删 throat-clearing："In this section, we will discuss..."、"It is important to note that..."。
- 删空泛形容词：novel/crucial/significant/robust 必须能被证据替换；否则删。
- 术语一致：同一概念一个词；缩写首次定义；数学符号与正文一致。
- 校准 hedge：有证据用 "shows"，有限证据用 "suggests/consistent with"，不要反过来。
- 禁用 AI 腔：delve、crucial、it is worth noting、in the realm of、a myriad of、not only...but also 滥用。
- 字数/页数符合 venue 要求（通常 ±10% 内），不要用注水或删关键信息凑。

## 9. 引用与证据绑定

- 每个事实/数字/claim 必须有引用或本文数据；引用零孤儿（正文 ↔ 参考文献一一对应）。
- 引用前核验：DOI/arXiv/URL 可解析、作者年份正确、内容确实支持该句；禁止凭记忆或摘要编造。
- 数字台账：同一数字在摘要/正文/表/图中出现必须一致；改一处要全局搜索。
- 引用格式按 venue（APA/IEEE/ACM/Chicago…）；DOI 尽量给全；优先最近工作与原始工作，少引二手综述。
- 自引比例过高要检查（一般 >15% 需说明）；过时引用（>10 年）除经典外要更新。
- 引用"缺失/空白"的声明要有检索证据（数据库、检索式、日期），不能空口说"没人做过"。

## 10. 返修与 rebuttal

- 逐条编号回复，覆盖所有 reviewer comment，不遗漏、不合并糊弄。
- 分类：editorial / scientific / statistical / policy / 无法解决；每条给"接受/部分接受/礼貌反驳 + 证据 + 修改位置"。
- 接受就改到位并指出位置；反驳要引证据/新增实验，不情绪化、不攻击审稿人。
- 不谄媚：审稿人错误时给理由；不 scope creep：只改被要求的，新增内容需作者批准。
- 补实验要写明设置与结果；来不及就诚实说明并列为 limitation，不编造。
- 回复后做一次 re-review：确认修改真的出现在论文里（不是只在回复信里）。

## 11. 投稿前检查表

- [ ] 标题/摘要/正文/图表数字一致；摘要无正文外 claim
- [ ] 每个 claim 有引用或本文证据；引用可解析、无孤儿、格式一致
- [ ] 主表含最强基线、同协议、seed 数、不确定性
- [ ] 至少一个反 claim 对照/消融；负结果与偏差已写
- [ ] Limitations 具体；声明齐全（数据/代码/伦理/贡献/COI/资助/AI）
- [ ] 图按最终尺寸可读、图注自含、正文引用每个面板
- [ ] venue 页数/模板/匿名/AI 政策核对（官方最新）
- [ ] 全文朗读一遍：每段有功能、无 AI 腔、无夸大

## 12. 反模式（来自 ARS anti-patterns，命中即改）

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 空泛词汇（delve/crucial） | 信息量低，暴露 AI 腔 | 用领域术语与具体动词 |
| 破折号打断论证 | 读者注意力被旁支带走 | 括号/逗号/重写 |
| Throat-clearing 开场 | 不提供信息 | 直接给 claim/发现 |
| 为凑长度注水/拆段 | 掩盖论证转折点 | 按论点需要给篇幅 |
| 编造引用 | 学术不端 | DOI/原文核验 |
| 谄媚式返修 | 接受所有意见，改坏论文 | 有证据地反驳/部分接受 |
| 返修 scope creep | 引入未被要求的新内容 | 只回应审稿意见 |
| 忽略 desk-reject 信号 | 浪费时间 | 检查 failure paths，必要时改投 |
